# Editing workflow: understand, discover, build, inspect, correct

An editing technique is an intended visual/audio behavior, not a command name. Combine primitives to reproduce the behavior. Do not restrict creative analysis to a predefined list of named effects or examples.

The default reference task is **technique transfer**, including references with different footage. Extract and reproduce the behavior, adapting anchors and framing to the current source. Do not demand pixel-identical scenery or turn uncertain landmark fits into required zoom values. Fill the intended picture before animating it. For new raw-footage projects the host removes confidently detected stable encoded padding from retained working copies; existing project canvases and explicitly requested borders are preserved.

Workers use the job-scoped `ai_editor` local MCP server. Start with `inspect_job`; inspect individual timed images with `reference_frames`; test curves with `evaluate_keyframes`. Only the lead can use `apply_edit_plan`, which executes the same validated native compiler against the candidate. `inspect_timeline` reads actual saved controls. Specialists/reviewers cannot write. Shell, desktop, arbitrary paths, uploads and paid calls are unavailable. MCP construction is not a visual match: host preview, file checks and technique review requirements still apply; normal jobs never open, close or capture CapCut.

Honor the controller's editing scope. With an explicit **Keyframes only** request, effects and material queries stay empty, audio stays unchanged, and no color/exposure animation is added. Focus the lead, motion specialist and reviewers on spatial movement, timing, easing, overshoot and settling. Do not attempt excluded reference effects or treat them as missing requirements. This is a per-request focus, not a global removal of effect tools.

1. **Understand the task.** A reference is optional. With instructions only, use the user's requested changes as acceptance criteria. With an image, analyze typography, composition, colors, hierarchy and geometry; it cannot establish temporal motion/audio. With a video, analyze cuts, source retiming, camera/subject motion, digital motion, effects, text, assets and sound separately. A public link must first resolve to accessible media through the host's reference reader.
2. **Measure the evidence.** Use source/canvas metadata and timed reference frames. Record technique IDs, reference intervals, confidence and uncertainty. The host must supply a contact-sheet timing map: row-major order, actual frame times, sampling FPS and video duration. Do not claim timing is unavailable when this metadata is supplied. Ask the host for denser frames around short transitions when needed. Separate source motion from imposed animation.
3. **Discover the installed tools.** Read the versioned runtime inventory and the relevant tool guide. Use MCP `discover_capabilities` for an unfamiliar operation or resource: it retrieves the installed command contracts and searches the pinned catalog, showing application adapter coverage separately. Learn options, timing units, easing behavior and output shape before proposing execution. Look for an existing native control, then combinations of controls, generated assets or a local composition. An absent adapter is different from an absent CLI capability; discovery does not itself execute an operation.
4. **Plan the whole edit.** Map every requested or observed technique to ordered operations, source intervals, asset dependencies, editable native components, preview representation and checks. Use keyframes for time-varying properties, with explicit times, values and easing. Use cuts/retiming for pacing, layers/blend modes/masks for compositing and local audio tools for sound. Do not describe a static pose as a complete animation.
5. **Create missing assets.** If the technique needs a shape, illustration, diagram, texture or motion graphic, design it from the evidence and generate an appropriate local asset through a registered host tool. Retain editable vector/code sources, alpha/transparency and provenance. Do not conclude that an asset-dependent technique is impossible merely because no image was supplied. Choose a reusable generation method, not a hard-coded asset for one reference. Keep captions and words in native text layers.
6. **Build through the host.** The worker proposes validated operations; trusted adapters execute them in the job/candidate. No arbitrary shell commands or executable scripts from task data. Do not invent resource IDs, command options, installed runtimes or operation success. Honor the supplied output contract. If it cannot express the required operation, identify the precise adapter/contract gap rather than pretending the installed CLI lacks the feature.

   Native effect discovery is automatic. When the official connection is available, the controller searches selected effects and resolves matching installed free resource bundles. It learns their named controls and invokes the local STDraft builder before translating output into the desktop candidate. The normal flow must not launch CapCut to acquire missing packages. Reuse installed resources and cached searches. Missing or ambiguous packages remain explicit limitations; consider supported combinations of native controls without changing the requested technique. Workers never download packages, control the desktop or silently substitute another effect. No cloud draft, footage upload, export or paid generation is used. Resource availability proves construction, not native appearance.

7. **Inspect and correct.** The host schedules relevant independent specialists before compilation; the lead integrates their corrections into one complete plan. Run structural, media and dependency checks, then inspect timed app-preview evidence and serialized native controls. Use explicit preview review mode; absent native capture alone is not a failure. Measure defects against the request/reference. Preserve technique IDs and controller-owned acceptance criteria. The manager independently checks coverage; the controller combines defects and repairs within its correction/deadline limits. A final-round defect is an unsuccessful candidate, never completion.
8. **Hand off accurately.** Distinguish a complete preview match, a partial candidate and a failed build. Original-project writes require passing file-and-preview review, unchanged evidence/assets and originals, a backup and explicit approval. A read-only process check requires the user to close CapCut before Apply; the app never quits or reopens it. Preserve intermediate work on failure.

Never use paid providers, API-key fallbacks, cloud rendering or generation credits. Never flatten the whole edit to hide missing native components. A reusable renderer and per-asset editable source are allowed design choices only when they preserve the promised editability contract and are represented honestly.

The correction count is a ceiling, not a target. Stop after the first passing comparison. Preserve accurate components and repair only demonstrated defects and their dependencies; do not add subjective polishing rounds. Reuse unchanged specialist assessments and generated assets. Absent native capture alone is not a blocker in preview mode. If a requested behavior cannot be assessed by the preview, report that precise limitation without spending repeated editing rounds or launching CapCut.

Tool recovery is bounded and evidence based. `INVALID_EDIT_PLAN` describes missing or invalid fields and supplies a repair hint. Repair the complete input, then retry; specialists should call `evaluate_keyframes` with `planJson=""` to inspect the host-saved complete plan instead of rebuilding it from a partial role view. Three identical invalid submissions exhaust that input's recovery allowance. Security/path/auth/runtime errors are not permission to relax checks. A confirmed successful retry means that tool request passed, not that the final edit passed. Preserve the candidate and report unresolved blockers when recovery fails.

Specialists receive task evidence and their relevant plan components, not the lead editor's authoring prompt. Explicit exclusions such as "no captions" do not schedule that role unless actual caption components need checking. Invalid specialist output gets one report-only repair with the validation error and allowed technique IDs; it must not restart construction. A missing final render report during pre-build consultation is expected, not a defect. Render/mix checks follow integration.
